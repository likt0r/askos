# Every list takes Regex entries; on the Allowlist they never allow strong Signals

Every list matched a domain and its subdomains. Some cases need a pattern instead: a family of lookalike names (`^npm-[a-z]+\.(com|net)$`), or names that differ in a varying label (`^mirror[0-9]+\.vendor\.example$`). The owner decided on 2026-11-04 (#2) that all four lists take regular expressions: the Allowlist, the Watchlist, the Legitimate domains and the Harmless marks.

A **Regex entry** has a pattern in place of the domain. It matches with `re.fullmatch` against the lowercased host name without its trailing dot: exactly the hosts it describes, no subdomains of its own accord. Domain entries keep their meaning. A record entry carries the pattern in the field `regex` instead of `domain`, a Harmless mark is the line `regex <pattern>`, and the CLI takes `--regex PATTERN` wherever it takes a domain; an entry is removed or changed by the same value it was added with. A domain and a pattern of the same text are two entries.

A pattern is checked when it is added, and again whenever a list is read, by the same rules in agentbox and in the proxy: they live in the classifier (`agentbox-suspicious`, `pattern_problem`), which the proxy loads and agentbox loads the same way.

- At most 200 printable ASCII characters without spaces (host names have nothing else, and the proxy log names a pattern as one word), and it compiles.
- No uppercase letters (host names are compared in lowercase, so such a pattern would never match; `(?i)` allows them), no backreferences, no lookarounds.
- No quantifier and no alternative inside a repeated group (`(a+)+`, `(a|ab)+`), and at most two quantifiers in a row that can take the same characters (`.*a.*b` is fine, `.*a.*b.*c` is not). The first rule is kept simple and so also refuses repeated groups a delimiter would keep fast, such as `^(?:[a-z]+\.){1,5}example\.org$`: a domain entry covers the subdomains instead (`example.org`), or the pattern does without the group (`^[a-z0-9.-]+\.example\.org$`). The host name comes from the VM, which could choose one to make a pattern backtrack; with these rules and hosts of at most 253 characters, matching takes well under a millisecond for typical patterns, and at worst, for a pattern at the limit of the rules against a 253-character host made to backtrack, about 60 to 150 ms (#2, fuzzed). That cost falls on the proxy of the VM that sent the host, which only slows itself; there is no cap on the number of patterns, each adds its own. Patterns are compiled once whenever a list is read again, not per connection.
- The breadth check: a pattern must match none of a fixed sample of unrelated hosts (common public domains such as `google.com` and made-up names, `BREADTH_SAMPLE`), so `.*`, `.*\.com` or `[a-z]+\.[a-z]+` are refused; long hosts near 253 characters, long labels and many labels are in the sample too, so a pattern that only asks for length or many labels (`^[a-z0-9.-]{80,}$`) is refused as well. The Watchlist does without it: a broad pattern there only raises false Alerts.

What a list does with a matching pattern:

- **Allowlist.** A pattern allows destinations, so it gets safeguards a domain entry does not need. It never allows a destination with strong Signals, checked on every connection the way Open web does it (`BLOCKED <host> (suspicious: <signals>)`), so `--force` does not apply to it; and while the Watchlist cannot be read it allows nothing (`BLOCKED <host> (Watchlist unreadable, regex entries closed)`), for the same reason Open web closes then. Domain entries are checked only when they are added, as before. Adding one first shows which hosts of the scope's proxy log of the last 7 days (`ALLOWED` and `BLOCKED` lines) it would allow, each with whether strong Signals keep it blocked, and needs an explicit confirmation (`--confirm-pattern`; `confirm: true` in the Control Room). The preview reads at most the newest 200,000 lines, so a VM that fills its log can push older hosts out of it; it then says so first, and how far back it reaches. Scope, temporary entries, notes, `uses_24h` and closing tunnels ([ADR 0005](0005-ending-access-closes-only-disallowed-tunnels.md)) work as for a domain: the proxy remembers which entries allowed a tunnel and logs `ALLOWED <host> (allowlist regex <pattern> <scope>)`, naming a domain entry first when both allow it.
- **Watchlist.** A matching pattern raises its category as a Signal (reason code `watchlist-regex`, with the pattern); removing or weakening a strong one needs `--force`, as for a domain.
- **Legitimate domains.** A matching pattern lifts only weak Signals (the young Feed, unusual TLDs, random-looking labels, many labels). Which strong Signals a domain would lift is checked when it is added ([ADR 0009](0009-watchlist-and-legitimate-domains-live-on-the-host.md)); for a pattern it cannot be, since it stands for hosts nobody can list. So a regex Legitimate domain never makes a destination with strong Signals reachable in Open web, needs no `--force` and takes none.
- **Harmless marks.** A matching pattern stops Alerts, as a domain mark does; blocking stays as it is.

`check-domain` and the Control Room name the entry that matched, domain or pattern; the proxy log names the Allowlist entry. A stored pattern the rules refuse (a hand edit, or a later Release with stricter rules or a larger breadth sample) counts as nothing, in the proxy as in agentbox, while the other entries of its list keep working: on the Allowlist it allows nothing, as a Harmless mark it silences nothing, and as a Legitimate domain it lifts nothing. On the Watchlist it would raise a Signal, so which destinations Open web must keep blocked is unknown: the Watchlist counts as unreadable for Open web and for regex Allowlist entries (ADR 0009) until the pattern is removed, while its other entries still raise their Signals and Alerts, and the detection self-test fails on it. The CLI and the Control Room list such an entry with the reason (`refused`), and it is removed by its pattern like any other; a record broken in its structure (a field missing, a pattern that is no text) stays broken as before.

## Consequences

- New refusals have codes (ADR 0012): `invalid_pattern` with the rule broken as the parameter `reason`, `pattern_too_broad` with the sample host it matches; an unconfirmed regex Allowlist entry is `confirmation_required`.
- `agentbox check-regex <list> --regex PATTERN [<host>...]` says whether a pattern can be an entry of a list, which hosts it matches and, for the Allowlist, what it would allow, for the Control Room's test field and preview. It changes nothing.
- The detection self-test covers one Regex entry per list, in lists of only its own test entries (the text files from before the records have no patterns): a Watchlist pattern raises its Signal, a Legitimate pattern lifts a weak Signal but not a strong one, a Harmless pattern stops an Alert, and an Allowlist pattern lets neither a destination with strong Signals through nor anything while the Watchlist cannot be read.
- JSON results of the list commands carry both `domain` and `regex`, one of them `null`; `agentbox harmless --json` lists objects instead of strings.
- The breadth sample and the rules are part of a Release: a later one may refuse an entry an earlier one took. That fails safe, as above: such a pattern counts as nothing (on the Watchlist Open web stays closed) until it is removed, and nothing else stops working.

## Considered Options

- Check a regex Allowlist entry's Signals only when it is added, like a domain: rejected. A pattern stands for hosts that may not exist yet; a lookalike or a Watchlist entry that turns up later would pass.
- Let `--force` lift strong Signals for a regex Allowlist entry: rejected. A forced domain entry lifts them for one known destination; a forced pattern would for every host it matches, including future ones.
- Let a regex Legitimate domain lift strong Signals, with `--force` always: rejected. The Control Room could never add one, and the check behind ADR 0009's `--force` rule cannot be done for a pattern at all.
- Translate patterns to globs or a restricted syntax of our own: rejected. Python's `re` is what the owner asked for, and the rules above keep it safe to match.
- Bound the matching time by a timeout instead of rules: rejected. Python's `re` cannot be interrupted, and the proxy matches in its event loop.
